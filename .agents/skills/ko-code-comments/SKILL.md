# 한국어 코드 설명 주석

사용자가 코드 파일 경로를 주고 코드 설명 주석을 요청하면 이 스킬을 사용한다. 파일 내용을 읽고 핵심 흐름과 복잡한 부분에 한국어 주석을 직접 추가한다.

## 작업 기준

- 기본적으로 전체 줄을 해설하지 말고, 코드만 읽어서는 놓치기 쉬운 목적·흐름·조건·부작용을 설명한다. 명백한 문법이나 변수 이름을 다시 말하는 주석은 쓰지 않는다.
- 코드에서 확인할 수 있는 사실만 설명한다. 함수나 값의 사업상 의미, 호출 맥락, 의도된 정책을 코드만으로 알 수 없다면 그 부분을 추측해 주석으로 쓰지 않는다.
- 주석을 달 위치와 의미가 불분명하면 파일을 수정하기 전에 사용자에게 구체적으로 질문하고 답을 기다린다. 분명한 부분은 먼저 설명할 수 있지만, 답변이 필요한 부분에는 추측성 주석을 넣지 않는다.
- 기존 코드와 동작은 유지하고 설명 주석만 추가한다. 주석 추가를 위해 줄바꿈·서식·이름·로직을 바꾸지 않는다. 개선점이나 오류를 발견해도 이 요청에 포함시키지 말고 별도로 알린다.
- 파일의 언어와 문법에 맞는 주석 표기를 사용하고, 기존 주석과 같은 내용을 반복하지 않는다.
- 요청된 파일이 프로젝트 밖에 있거나 경로를 찾을 수 없으면 수정하지 말고 사용자에게 경로를 확인한다.

## 진행

1. 경로가 가리키는 파일을 읽고 언어, 주요 흐름, 이미 있는 주석을 확인한다. 설명에 필요한 관련 코드가 저장소 안에 있으면 필요한 만큼만 읽는다.
2. 코드만으로 설명할 수 있는 내용과 사용자 의도 확인이 필요한 내용을 구분한다. 확인이 필요하면 판단이 필요한 구체적인 지점과 선택지를 짧게 묻고 답을 기다린다.
3. 확인된 내용과 코드에서 분명한 내용만 한국어 주석으로 추가한다. 독자가 코드를 따라가는 데 도움이 되도록 가까운 위치에 두고, 짧고 구체적으로 쓴다.
4. 변경 diff를 확인해 요청된 파일에 주석만 추가됐는지 검토한다. 기존 코드 변경이 섞였으면 해당 변경을 되돌리고 주석만 남긴다.
5. 결과를 간단히 보고한다. 수정 파일, 주석을 추가한 핵심 부분, 사용자가 직접 확인할 방법을 알려준다. 검증하지 않은 동작을 검증했다고 말하지 않는다.
